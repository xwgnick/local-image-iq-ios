## 最新阈值契约

- 可选范围由 0.90…0.99 放宽至 **0.50…0.99**，两端均包含。
- 默认值仍为 **0.96**，步长仍为 **0.01**；滑块使用整数 50…99 再除以 100。
- 低于 0.90 时提示：可能只是场景相近，请逐张核对后再勾选删除。
- 数值是向量余弦相似度阈值，不是概率、重复像素比例或“可放心删除”的置信度。
- 即使高阈值也不保证同一主体、事件或照片可互相替代；不会自动选保留项、勾选或删除。
- 用户可自行试 0.85、0.80、0.75，再显式点“重新分组”；不保证一定出现分组。
- 全组每两张均须达到阈值的规则不变；不是只要求相邻照片相似的链式分组。
- 调整阈值会使旧结果失效，不自动重扫；打开页面或回前台也不自动扫描。

## 已恢复的结果发布实现

- `PhotoRevisionBatchReading.currentRevisions(ids:)` 提供可选的批量元数据读取能力。
- 生产实现对非空 ID 集合使用一次 `PHAsset` fetch，替代发布时逐 ID fetch；保留旧接口回退。
- 批量核验仍要求数量、ID 集合、修改时间和创建时间一致；不依赖返回顺序。
- 批量读取失败不会退回逐 ID 读取来掩盖错误，也不会伪装成成功零组。
- `prepareForPublication()` 是非 actor 的 async 方法，在当前 Swift 5 模式下使用 generic executor。
- 耗时的成员访问校验离开 `MainActor`；这不是删除权限或版本核验。
- await 返回后重新检查取消、请求 token、前台状态和阈值，再执行轻量 epoch 校验。
- 最后这道校验与结果发布之间没有 await，避免旧会话在异步返回后直接发布。
- worker 原有三次完整照片快照核验（开始、计算前、计算后）全部保留，包括最终完整快照。
- 不削减授权范围或撤权检查；取消仍等待旧任务排空，旧结果不能覆盖新请求。

## 进度与页面状态

- 新增 `isValidating`，表示计算结束后仍在核验结果是否可以发布。
- 进度末端显示“分组计算已完成，正在核验照片访问…”。
- 原进度总数仍是参与分组计算的候选数，**不是整个操作的完成百分比**。
- 不添加虚假进度、倒计时或人为延迟；100% 后仍可能有完整快照与发布核验工作。
- 成功零组会发布候选数及空结果说明；校验失败不发布结果，显示通用失败提示。
- 本批不新增自动关闭逻辑，也没有证据支持另加“自动关闭修复”。
- 用户仍可通过“完成”等既有操作显式关闭；删除中的关闭限制保持不变。
