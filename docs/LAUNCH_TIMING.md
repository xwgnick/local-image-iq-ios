## 在哪里截图

1. 安装包含该功能的版本，正常打开 App，等加载完成。
2. 进入 **设置 → 调试工具 → 打开“显示调试工具”**。
3. 展开 **诊断信息 → 启动耗时**。
4. 截下版本、总耗时、最慢阶段和分段列表；build 19 还需包含“并行任务”区的时长、状态和开始偏移。长页可分两张；build 18 没有该并行区。

不需要先开调试再启动：每次启动都会自动记录，开关只控制入口展示。进入设置、刷新统计、搜索、更新索引或普通回前台不会改写该启动记录。不要为了测时重建或清除索引。

记录仅保存在本进程内存。退出进程后清空，重新打开会产生新记录；仅把 App 切到后台再回来通常不是新的进程启动。若有中断恢复／手动重试，会另存对应尝试，旧记录保留在“此前准备”里。发生中断时该次记录立即冻结，未结束分支截断并标为“中断”；**冻结后共享任务继续加载或退出的时间不计入该次记录**，迟到完成也不能将其改成成功。

## 计时范围

总耗时从 `beginLaunch()` 入口到准备结果发布为就绪／失败／中断。包含入口工作、调度、等待前一个取消任务排空、真实准备和结果返回；**不包含 iOS 进程启动、AppState 构造、根视图建立、根任务获得调度之前的时间，也不测首页第一帧绘制**。不能把它称为“手指点击图标到首页完全显示”的总时长。

计时采用 `ProcessInfo.systemUptime` 单调时间，不受系统日期校时影响。分段是**经过时间**，含 I/O、框架与 actor 调度等待，不是 CPU 独占时间；不从单次分段直接推断硬件瓶颈。

build 19 首次实际加载的固定主分段（相邻边界划分的墙钟经过时间）：

- 入口与权限状态
- 调度／等待前任务
- 进入准备任务
- 地点元数据（非地图）
- 模型准备入口
- 模型资源检查
- 并行准备模型（总等待）
- 汇总模型并发布
- 读取已存索引统计
- 返回／发布就绪

“并行任务（时间重叠，不相加）”单列加载分词器／加载图像模型／加载文本模型，按此固定顺序展示。每项显示实际经过时长、完成／失败／中断，以及“启动后 +… 秒开始”：偏移相对于**整次启动准备入口**，不是并行父阶段起点；分支从实际执行开始计时，不从入队计时。未执行的分支不补行。

复用模型时显示“复用已加载模型”，等待已在运行的共享初始化时显示“等待已有模型任务”，不编造这两种情况的独立加载子步骤。首次尝试未必对应空的操作系统／Core ML 缓存；重试也可能受此前模型准备影响。

**总耗时只由主分段构成；三个分支相互重叠，既不相加，也不再次加进总耗时。**“最慢阶段”也只比较主分段。并行父阶段含排队、分支启动时间差及结束／取消时等待子任务全部退出，可能长于最慢分支；任务组退出后才进入“汇总模型并发布”。但准备中断即时冻结的边界优先，不包含冻结后的加载或排空时间。

显示为秒，保留三位小数；显示后的四舍五入总和可有微小差异。失败只包含实际到达的阶段，不给未执行阶段填假耗时。build 18 的三项加载是顺序主分段，不应套用 build 19 的并行解释。

## 隐私与成本

仅记录进程内尝试／分支标识、固定阶段枚举、时长、开始偏移、尝试类别、通用结束状态和当前应用版本／build。没有照片 ID、照片内容、查询、GPS、原始异常或文件路径，不联网、不上传、不落盘。图标页不显示计时信息。

锁仅保护少量内存标记，不跨 await。生产协调器保留共享一次初始化、单个调用方取消不取消其他调用方准备的语义；并行 helper 负责失败／取消后的子任务排空。记录器结束后忽略迟到标记，每次尝试只生成一份报告。关闭调试入口不重置报告或搜索设置。
