# 相似清理错误分类 — 0.11.1 / build 31

## 当前边界：实现完成，原生验证及交付待完成

用户在 build 30 **刚进入相似清理**时看到“请确认照片访问权限”，此前可用。已确认旧状态层将所有非取消的恢复、计算及发布失败统一改写为权限提示；该文字不能证明设备确实失去 Photos 权限。

本次修正错误分类和可见诊断，**不是已定位或已修复未知手机根因的声明**。新恢复流程在判断分组缓存是否存在之前会检查 Photos、资源和图像索引源；锁检查不可用、真正存在写事务、辅助文件、源变更等原来都可能被统一误报。尚无手机原始返回码，不能推定具体一种已经发生。

## 变更

- 普通弹窗第一行只显示一次固定短码、固定阶段及必要的 errno／SQLite 数字返回码。无需开启调试页面。
- 分别保留恢复、计算、结果发布、选择核验的操作；阶段覆盖 Photos、资源、索引路径、源打开／核验、索引读取、缓存读写和计算。
- 真正的权限错误才提示系统 Photos 权限；未知错误保持未知，不借用权限或磁盘损坏结论。
- 区分 `SG-SOURCE-LOCK-CHECK`／`SG-SOURCE-FILE-CONTROL` 等检测失败与 `SG-SOURCE-WRITER` 的实际占用；单有辅助文件不等于已证实写入事务。
- 只保留允许列表中的类型和数字，不保存或显示未知错误 description、NSError domain/userInfo、SQLite errmsg、路径、照片 ID、OCR、查询或模型身份。
- 取消保持取消，晚到的错误不能覆盖当前状态。选择失败仍按既有逻辑失效，正常生命周期重新核验语义不变；未新增自动重试、回退计算或后台索引。
- 源失效不能降为可选保存警告；已捕获的致命源诊断直接保留首因，不被稍后的 Photos 错误替换。仅可选缓存写失败准备继续使用结果时，仍先核验两个来源。

## 未改变

不清图片／OCR 索引或派生缓存、不迁移 schema、不修改模型／图像策略／分组算法身份、不绕过锁／文件／Photos／删除安全检查、不启用搜索式无监视器回退。阈值、主导航、OCR 开关、搜索两列／12 张分页、清理五列和系统删除流程不变。没有实际读取或删除用户照片。

升级沿用同一 Sideloadly Apple 账号和有效 Bundle ID **覆盖安装，不卸载、不清库、不为升级重建**。如果仍失败，只需截图带错误码的普通弹窗；不要要求用户寻找未记录的旧诊断。
