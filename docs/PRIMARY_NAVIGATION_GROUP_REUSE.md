# 双主功能首页与分组结果复用

## 当前状态

**0.11.0 / build30：实现中，尚未交付。**用户于2026-10-07确认V3设计及首次自动分组交互；最近交付仍为build29。原生编译、测试、截图及设备包结果待补充。

## 已批准交互

- 底部两个等宽主入口“照片搜索 / 相似清理”，默认搜索；两页保持身份，切换不重建搜索草稿、结果及滚动视图。后台仍按原访问安全规则清除实时结果。
- 左上“我的图库”、右上设置。原来位于搜索筛选旁的小清理按钮改为主标签；搜索隐藏时不因预创建的底部几何继续翻页。
- 搜索框下“筛选”旁直接显示“照片文字”开关；右侧说明精确为 **“用照片里的文字进行搜索”**。开关仍默认OFF、沿用既有持久化；开启不自动OCR。
- 文字识别保持独立手动建立／更新、暂停及错误提示。设置和图库只保留索引管理，不再藏主要开关；关闭增强不会删除旧文字。
- 清理默认阈值 **0.80**，整数80持久保存，范围仍0.50–0.99、步长0.01。仅在设置显示滑杆，修改后需重新分组，不自动计算。
- 第一次真正进入清理页且权限／图片索引／模型状态就绪时，先恢复已保存结果；仅无历史结果时自动分组一次。启动及搜索页不提前计算，不自动索引图片或文字。
- 成功零组也是已完成结果。普通标签往返直接复用内存结果和已提交选择；重启／后台恢复核验缓存后复用，不重新计算照片对。
- 相关输入改变则提示手动重新分组；不能仅检查张数。失去权限或删除的成员不会继续作为可删除选择。新照片未进入图片索引时，仍需用户手动更新索引。

## 有效性与保存

- 独立派生缓存存于图片索引目录：完成分组ID／完整修订信息／最小相似度／统计与分组照片的原始Float向量二进制；不存照片像素、地点或OCR正文。不改源索引schema。
- 输入身份包括完整授权ID及修改／创建时间、实际授权状态、阈值、模型／图像输入策略／分组算法版本，以及活动图片索引行的图像BLOB内容指纹。相同张数替换、修改向量但不改revision也能失效。
- 恢复不解码源向量JSON、不推理、不读取Photos像素、不重新分组；会读取并hash活动可访问图片BLOB及核验Photos元数据，所以**不是零I/O或瞬时恢复承诺**。
- 当前冷恢复为两次完整Photos元数据和两次源BLOB扫描；首次缓存缺失后再计算的路径会重复初始检查。复用避免成对相似度计算，不宣称已消除全部首入延迟。
- 活动结果绑定只读SQLite连接的data_version、文件身份及写锁检查，发布前仍有便宜的同步校验；源变化不能降格为可选缓存错误。跨PhotoKit／SQLite最后检查后的变化不是可原子锁定的事务。
- 原有完整分组权限检查保留；无generation的注入库额外在发布前核验完整ID/revision，包含未成组／未索引成员。
- 收藏／相册通知本身不触发重新计算：只要完整修订和图片内容身份相同，重新绑定当前验证器即可复用。若系统也改变照片revision，仍按变化处理，不能无证据忽略。
- 二进制缓存校验完整性、结构和768维单位向量；受系统文件保护、排除备份、同目录原子替换。损坏／陈旧缓存不是“首次缺失”，提示手动更新；不会偷偷重算。
- 保存失败不阻止本次有效结果使用；服务保留完成结果的内存副本，无关通知后仍可重验复用。未持久保存时说明下次重启可能需重新分组。
- 切页取消未完成读取及临时拖选，不取消已提交的系统删除。删除确认继续绑定精确ID/revision，无自动选择、留一张或删除策略变化。
