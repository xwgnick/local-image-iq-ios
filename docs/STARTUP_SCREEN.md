## 行为

- 系统静态 Launch Screen 不执行任务；此处是 App 根入口创建后、首页之前的原生 SwiftUI 准备页。
- 沿用 B 青绿色主题，跟随系统浅／深色；品牌、用途说明、真实任务阶段及系统不定进度指示。
- 真实阶段为 `checkingLibrary`（检查图库）和 `preparingSearch`（准备搜索），不是由计时器模拟进度。
- 不显示虚构百分比或 ETA，没有最短停留时间、计时跳转或生产超时。
- 冷启动先做完整授权图片快照／失效记录清理／地点包准备，再加载主图像模型、文本模型和分词器；加载完成后再核对一次授权与修订，防止长时间准备期间的变化被忽略。
- 只预热主图像模型、文本模型和分词器，不创建／加载额外 19 个索引模型实例；不读取 Photos 像素、不预测／计算照片向量、不建立照片索引、不联网、不下载 iCloud 图片或翻译语言包。
- 成功后进入原首页；首次未授权也是正常情况，仍由用户主动点击“选择照片”才请求系统权限。
- 启动失败停在明确错误页，提供“重试”和“先进入应用”。继续进入不把失败当成功：保留原错误与现有搜索守卫，完整搜索仍会验证模型和向量。
- 启动中进入后台会取消本次前台工作；回来后通过同一串行任务链等待旧任务真正退出，再重新准备。迟到回调／完成不能发布到新尝试。
- 已完成启动后，切回 App 仍是 build 14 的轻量 refresh，不再次进入启动页或完整模型预热。已失败的启动不因前后台切换自动无限重试。

## 不应误解的边界

这是等待位置和冷启动资源准备时机的调整，**不是全缓存预热，不保证进入首页后没有后续等待或零延迟**。
完整向量读取、数值验证、查询翻译／编码仍在真实搜索时执行，图片显示也按实际操作执行；没有新增常驻全图库内存缓存。
真实权限／图库变化仍会触发必要刷新。

**build 14 的元数据／已知失败语义保留**：普通 refresh 继续只检查资源元数据，不保证运行时已经加载。
用户在启动错误页明确选择继续时保留原错误；后续资源检查可能重新显示就绪，但不证明已知运行时失败已修复。
元数据计数也不证明向量健康，坏向量可能被计数；实际搜索仍会调用完整准备和向量校验，损坏模型／向量不能绕过校验进入排名。
不新增锁死恢复或强制清库策略。

模型、20 路并发、HQ224／Fast、排名、翻译策略、默认 3 张／60%、SQLite schema 与缓存身份不变。
用**原 Sideloadly Apple 账号／原有效 Bundle ID 覆盖安装**，不卸载、不 Clear index；build 10+ 当前策略有效
图像／地点索引和就绪语言包沿用，**不重建、不必 Index / resume**。安装见 [WINDOWS_IPHONE_INSTALL.md](WINDOWS_IPHONE_INSTALL.md)。
