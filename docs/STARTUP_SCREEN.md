# 冷启动准备页 · 0.5.2（build 15）

2026-09-29 用户要求：把冷启动检查放在启动页，准备完成再进入应用，不要先显示首页再等待。目前为实现记录，尚待完整原生运行和新 IPA 校验；当前已交付版仍为 0.5.1 / build 14。

## 行为

- 系统静态 Launch Screen 不执行任务；此处是 App 创建后、首页之前的原生 SwiftUI 启动页。
- 沿用 B 青绿色主题，跟随系统浅／深色；品牌、用途说明、真实任务阶段及系统不定进度指示。
- 不显示虚构百分比或 ETA，没有最短停留时间、计时跳转或生产超时。
- 冷启动先做完整授权图片快照／失效记录清理／地点包准备，再加载主图像模型、文本模型和分词器；加载完成后再核对一次授权与修订，防止长时间准备期间的变化被忽略。
- 只预热主模型，不创建额外 19 个索引模型实例，不读取照片像素、不预测、不建立照片索引、不下载 iCloud 图片或翻译语言包。
- 成功后进入原首页；首次未授权也是正常情况，仍由用户主动点击“选择照片”才请求系统权限。
- 启动失败停在明确错误页，提供“重试”和“先进入应用”。继续进入不把失败当成功：保留原错误与现有搜索守卫，完整搜索仍会验证模型和向量。
- 启动中进入后台会取消本次前台工作；回来后通过同一串行任务链等待旧任务真正退出，再重新准备。迟到回调／完成不能发布到新尝试。
- 已完成启动后，切回 App 仍是 build 14 的轻量 refresh，不再次进入启动页或完整模型预热。已失败的启动不因前后台切换自动无限重试。

## 不应误解的边界

这是等待位置和冷启动资源准备时机的调整，不是整个 App 零等待。完整向量读取、数值验证、查询编码、翻译和图片显示仍按实际操作执行；没有新增常驻全图库内存缓存。真实权限／图库变化仍会触发必要刷新。

普通 refresh 继续只检查资源元数据，不保证运行时已经加载；用户在启动错误页选择继续后，后续轻量刷新可能重新确认元数据可用，但实际搜索仍会调用完整准备，损坏模型不能进入排名。不新增锁死恢复或强制清库策略。

模型、20 路并发、HQ224／Fast、排名、默认 3 张／60%、SQLite schema 与缓存身份不变。覆盖安装沿用原账号和 Bundle ID，不卸载、不清索引、不重新准备照片。
