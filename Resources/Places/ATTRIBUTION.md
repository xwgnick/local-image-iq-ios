## Derivation, parent labels and historical names

The builder uses the eight pinned upstream **simplified** datasets, verifies each
source's SHA-256 before parsing JSON, and performs no additional simplification.
Valid Polygon and MultiPolygon coordinates, islands and holes are retained.
Longitude unwrapping is used only for planar geometry predicates. Invalid
geometry may be repaired with Shapely `make_valid`; polygon components can be
extracted from collections, and unsupported non-polygon components are discarded.
The generated manifest records repairs, failed repairs, exclusions and counts.

Labels use the upstream `shapeName` (with surrounding whitespace trimmed), an
optional derived ADM1 parent for ADM2, and the country. Missing, blank or non-text
names are not emitted as invented place names. Their usable geometry remains in
the parent candidate set so an unnamed overlapping region cannot silently turn
an ambiguous assignment into a named match. Upstream `shapeID` values are retained
as source identifiers; missing identifiers use a boundary-ID/row fallback and
duplicates are recorded with a row tie-break.

Parent method: same-country ADM1 bounding-box candidates, then
`covers(ADM2 representative_point())`; exactly one candidate is required, including
unnamed candidates. Ambiguous, absent or unnamed parents are omitted. This is a
planar, longitude-unwrapped administrative approximation, **not an official hierarchy**,
not full child containment, not a nearest-place guess, and not a photo's position.

Historical names and boundaries reflect the recorded source years (China ADM1
2019 / ADM2 2017; France 2022; Germany 2021; Netherlands 2022), not necessarily
current administrative names, boundaries or addresses. Differing source years
can also make inferred parent relationships uncertain. ADM1/ADM2 and canonical
values are the source's classifications, not a claim that all countries share
the same administrative structure. Coverage is limited to these source datasets,
not worldwide coverage or a statement about disputed boundaries.

## Attribution carried with the generated pack

By default the builder requires this document and copies its complete UTF-8 text
into the generated manifest's `attribution.text`, alongside license-reference
URLs, the text's SHA-256 and byte count. The manifest also contains each source's
exact metadata, verified input hash/length, generated output hash/length, processing
counts, parent method, and Shapely/GEOS versions. Keep the generated manifest with
the pack when bundling it in the app so this notice and all source-license records
travel with the data. This describes the builder's output contract; it is not a
claim that an app build or distribution has already been verified.

This notice contains public provenance metadata only: no coordinate arrays,
photos, photo locations, indexes or personal data. The boundary builder does not
read those private inputs. The generated geometry pack necessarily contains the
public administrative boundary coordinates, separately from this notice.
