## 固定九步：完成数 / 9

`StartupStep` 的完整列表如下；每项最多计一次，模型相关项恰好五项（第 3–7 项）：

| 项 | 标识 | 完成条件 |
| --- | --- | --- |
| 1 | `entry`：入口与权限状态 | 入口与权限状态准备返回，不枚举照片。 |
| 2 | `places`：地点元数据 | 轻量地点元数据检查返回，包括明确不可用的结果。 |
| 3 | `resources`：模型资源检查 | 必需资源与模型清单契约检查完成。 |
| 4 | `tokenizer`：分词器就绪 | 分词器实际加载成功。 |
| 5 | `imageModel`：图像模型就绪 | 主图像模型加载并通过契约检查。 |
| 6 | `textModel`：文本模型就绪 | 文本模型加载并通过契约检查。 |
| 7 | `assembly`：模型组装完成 | 完整且验证过的模型与分词器集合已发布。 |
| 8 | `counts`：索引统计完成 | 只读已有索引统计返回。 |
| 9 | `ready`：启动就绪 | `AppState` 已实际发布成功就绪，而不只是模型加载结束。 |

生产比例严格为 `n/9`，不是预计时间或工作量比例。分词器、图像模型、文本模型仍并行，完成顺序与耗时可不同，九步列表不要求三条分支串行；长时间停在某个分数是正常且诚实的表现。视觉附件中的 37.5% 仅为绘制夹具，不是生产步骤值。

## 尝试、失败与共享加载

- 每次尝试独立计数，完成集合取并集，重复或乱序通知不重复计数、不倒退；重试或中断后恢复可重置为新尝试。
- 只有成功发布 `AppState.launchPhase = .ready` 后才标记第九步；仅在九项全部完成且本次上下文有效时写入成功记录。缺步骤不补齐，不靠延时或动画凑满。
- 失败、取消或进入后台：隐藏条，冻结本次已完成集合，不写本次成功记录；不抹除已有成功记录。原有内存启动耗时报告保持原契约，与这里的持久化成功记录不同。
- 失败后仍可轻点图标重试、长按显式“先进入应用”（含辅助功能操作）；后者只开放恢复入口，不补第九步、不写成功记录，也不解除模型、搜索与索引原有就绪守卫。
- 共享模型任务拥有独立进度记录器；旧尝试冻结或移除观察者不取消共享加载。新观察者回放已完成集合；已获准执行的旧回调可能晚到，由尝试身份与前台状态守卫拒绝。移除观察者不是等待所有回调退出的屏障。
- 通知乱序或错过中间通知由完整集合回放、并集及成功返回时核对五个模型步骤处理；共享进度通道异常缺失时抛出可处理的契约错误，不使用断言崩溃，不伪造完成，也不额外加载模型。

**已知限制：**沿用旧的串行作业契约，新尝试必须等待已取消的前一作业真正退出；等待期间进度可能停在 **1/9**，直到新 worker 获得执行机会并取得已完成模型步骤的回放／复用结果。不会为改善观感提前推进，也不会另起模型加载。已有针对性交错测试不等于覆盖所有真实多调用方取消、重试交错。

## 显示判断与最小持久化

- 生产入口显式注入 `StartupHistoryStore(defaults: .standard)` 与 `StartupContext.current()`；测试不隐式使用全局存储。
- 上下文仅读取小模型清单并验证，结合 bundle 与资源路径身份、Bundle ID、版本／build、OS 和模型配置身份生成 SHA-256；资源路径只作身份输入，不遍历权重或探测系统缓存。
- `UserDefaults` 的版本化键 `startupPreparation.success.v1` 只保存 `schema = 1` 与 **64 位十六进制摘要**，不保存原始清单、路径、耗时或逐次启动历史；仅完整九步成功更新为本次上下文。
- 精确相同上下文曾成功时，正常快速启动隐藏进度条；这只是低慢启动风险提示，**不是 Core ML 缓存命中证明**，不跳过真实准备。首次、旧版本没有记录、重装导致记录缺失或安装路径变化、build／OS／配置变化、上下文缺失或记录损坏时显示条。
- 系统可能静默回收缓存而上下文不变：仍未完成时，**8 秒仅触发显示**，高于此前旧版手机约 5 秒的观测基线；不代表其他手机的保证值。它不改变完成数、不预估剩余时间、不终止任务，不是超时、截止时间或最低展示时长；旧尝试的延迟回调不能影响新尝试或已就绪界面。
- 不新增用户数据、照片、GPS 或原始路径持久化，不新增遥测；不为判断显示而读取／哈希权重、预加载额外模型或进行缓存探测。
